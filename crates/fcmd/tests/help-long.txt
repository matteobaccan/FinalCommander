FinalCommander is a two-panel file manager for the terminal that works the same way on Linux, macOS and Windows: one program, one set of keys, one configuration file.

Two panels side by side, the function keys along the bottom saying what they do right now, and a command line underneath. Copying, moving and deleting run as jobs with progress and a way to stop them. Archives open as directories. The viewer streams a file of any size and disassembles a binary; the editor edits lines or bytes. SFTP panels are panels like any other.

The keys are FAR's by default, with a Midnight Commander profile; every action is a named command and every command can be bound to a key. Press F1 inside the program for the manual, whose key and command chapters are generated from the keymap in force.

Usage: fcmd [OPTIONS] [PATH]...

Arguments:
  [PATH]...
          Directory for the left panel, and optionally for the right one

Options:
      --config <FILE>
          Use this configuration file instead of the default one

      --plugins <DIR>
          Use this plugins directory (the only directory fcmd ever reads besides the config file)

      --theme <ID>
          Theme id (commander, far, black, white, matrix, tron, blade, github-dark, delphi-dark-2027, or an external one)

      --keymap <NAME>
          Keymap profile: a built-in one (far, mc) or a [[keymap]] block from the config file

      --lang <TAG>
          Interface language: en, it, de, fr, es, ru, zh, or auto

      --set <KEY=VALUE>
          Override a setting, e.g. --set panel.show_hidden=true

      --view <FILE>
          Open this file in the viewer; leaving the viewer ends the run

      --edit <FILE>
          Open this file in the editor; a name that is not there starts an empty file

      --diff <A> <B>
          Compare these two files side by side

  -P, --printwd <FILE>
          Write the directory the panel ended in to this file, for a shell wrapper to read.
          
          A process cannot change its parent's working directory, so leaving the shell where the panel was takes two halves: this, and a function in the shell. `--shell-init` prints the function. Midnight Commander spells this `-P`, and so does this.

      --no-save
          Read the histories and the panels' places, but write nothing back on the way out.
          
          For a second copy opened for a quick job beside the main one: without it, whichever quits last writes the state file, and the main one's histories lose to the side job's. FAR's issue #1046.

      --shell-init <SHELL>
          Print the shell function that makes the shell follow the panel, for this shell.
          
          Add `eval "$(fcmd --shell-init bash)"` to the shell's startup file — one line, and no file installed anywhere, which is the rule in SPEC 11 §1.
          
          [possible values: bash, zsh, fish, powershell]

      --list-themes
          List the themes found in this run and where each came from

      --list-commands
          List every command id (the vocabulary keys, menus and plugins bind to)

      --list-languages
          List the interface languages compiled in

      --check-keymap
          Validate the keymap and print the resolved bindings

      --export-theme <ID>
          Print a theme as TOML, to start an external theme from

      --dump-config
          Print the effective configuration

      --paths
          Print where the config file, the state file and the plugins directory are

      --list-plugins
          List the plugins found in the plugins directory

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version
